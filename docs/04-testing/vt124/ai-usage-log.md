## AI output that needed verification

The original generated byte-limit test looked sufficient: it checked an exact
1MB record, +1 byte and multibyte overflow. But it could not detect checking each
record independently instead of enforcing the total batch budget. Independent
review identified the gap; T15b now uses two individually small records whose
combined byte total is exact/+1. This is test-oracle improvement, not a claim of
a production bug that was reproduced.

A second output requiring verification is the generated async/Promise.all load
harness: it looks like concurrent users, but inspection confirms synchronous
parsing in one event loop, not HTTP sessions or120 workers. Its clock therefore
starts at a common barrier and its scope explicitly excludes input preparation
and real-user capacity. All120 outcomes, including any errors, contribute raw
latencies; assertions are outside the catch that records failures.
